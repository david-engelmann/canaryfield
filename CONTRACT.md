# canaryfield contract

This contract is the executable spec for canaryfield. Every obligation below maps to at least one named test in the test suite. An obligation is met only when its tests pass.

## Setup obligations

- SETUP-1 The seed files stay intact. README.md keeps the seed description and licence sections, LICENSE keeps the MIT text, and .gitignore keeps the seed rules. Proven by test_seed_files_present.
- SETUP-2 The README status section tells the truth about the build state. It states the local seed, the blocked remote seed, the contract state, the slice state, the closed round count, and the pending AGENTS.md. Proven by test_readme_status_is_honest.
- SETUP-3 Continuous integration runs the same command as the local gate. The workflow runs python -m pytest on push and on pull requests. Proven by test_ci_runs_the_local_gate.
- SETUP-4 No AGENTS.md exists in this repo until the canonical template is supplied by the main chat. Proven by test_no_agents_md_yet.
- SETUP-5 Every fixture and example in this repo is synthetic and written for this repo. No real traces, real names, or private detail appear anywhere. Proven by the sanitization self scan reported with every change.

## Slice obligations

- SLICE-1 The seed registry holds exactly twelve seeds with unique stable ids. Seed zero has id seed-00 and plants the stale version string 9.9.9. Proven by test_registry_has_twelve_unique_seeds and test_seed_zero_is_the_stale_version_string.
- SLICE-2 Every seed carries a name, a defect class, and an applicability check. A seed that does not apply to a target is recorded as not applicable and is never counted as caught or waved through. Proven by test_seed_metadata_is_complete and test_inapplicable_seed_is_recorded_not_applicable.
- SLICE-3 Planting happens only in scratch copies. The target tree is byte identical after any run, proven by a hash walk taken before and after. Proven by test_target_tree_is_byte_identical_after_a_run.
- SLICE-4 Gates are named commands supplied by the operator. Every gate runs once against a clean scratch copy and once against each planted scratch copy, each run under a timeout. Proven by test_gate_runs_on_clean_and_planted_copies.
- SLICE-5 Catch scoring follows one rule. A seed is caught for a gate when the gate exits zero on the clean copy and non-zero on the planted copy. A seed is waved through when the gate exits zero on both copies. Proven by test_caught_and_waved_scoring.
- SLICE-6 A gate that fails on the clean copy is reported as gate broken for every seed. A broken gate is never reported as catching anything. Proven by test_gate_failing_on_clean_copy_is_broken.
- SLICE-7 The catch table is the report. It carries one row per seed and one column per gate, with each cell holding exactly one of caught, waved through, not applicable, or gate broken. The same facts render as plain text and as JSON. Proven by test_catch_table_shape_and_statuses and test_report_renders_text_and_json_with_the_same_facts.
- SLICE-8 Slice 1 proves the machinery on synthetic targets only. Nothing is planted in a live tree, and the scratch clone proving run against a real portfolio tree is future work, stated as such in the README. Proven by test_example_target_is_synthetic and by the README honesty test in SETUP-2.

## Slice 2 obligations

- SLICE2-1 A git branch planting mode exists beside the copy mode. In git mode the tool clones the target into a scratch clone under the work root and plants only inside that clone. The target itself is never checked out, committed to, or written to. Proven by test_git_mode_target_git_state_untouched.
- SLICE2-2 In git mode every applicable seed is committed on its own throwaway branch in the scratch clone. The branch name is canaryfield/seed- plus the seed id. Gates run in a checkout of that branch. A seed that does not apply gets no branch and stays recorded as not applicable. Proven by test_git_mode_plants_each_seed_on_its_own_branch and test_git_mode_inapplicable_seed_gets_no_branch.
- SLICE2-3 Git mode scoring follows the same rule as copy mode. A seed is caught when the gate exits zero on the clean checkout and non-zero on the seed branch checkout, and waved through when it exits zero on both. A gate that fails on the clean checkout is gate broken and catches nothing. Proven by test_git_mode_scores_caught_and_waved.
- SLICE2-4 The scratch clone is deleted at the end of a run unless the operator asks to keep it. Proven by test_git_mode_scratch_clone_deleted_by_default and test_git_mode_scratch_clone_kept_on_request.
- SLICE2-5 Copy mode does not change. The slice 1 example catch table regenerates byte identical under copy mode, and every slice 1 obligation above keeps passing. Proven by test_copy_mode_example_regenerates_byte_identical.
- SLICE2-6 Two gates can judge the same field in one run and their verdicts are reported side by side. A second committed example shows two gates over the same target with at least one seed where the gates honestly disagree. Proven by test_two_gate_example_shows_an_honest_disagreement and test_two_gate_run_scores_each_gate_on_its_own_evidence.
- SLICE2-7 The seed registry can be written out as a versioned seed pack file. The pack carries the format string canaryfield-seeds/1 and one entry per seed with id, name, defect class, and description. Loading the pack returns the same twelve ids and defect classes as the built in registry. Proven by test_seed_pack_round_trip and test_seed_pack_via_cli.
- SLICE2-8 Git mode refuses a target that is not a git repository. The refusal is a clear error before any planting happens, never a silent fall back to copy mode. Proven by test_git_mode_requires_a_git_target.

## Round 1 review fix obligations

The Round 1 audit and red team found ways a run could harm material outside its own scratch and ways its refusals and pack loading were weaker than the claims around them. The obligations below amend the slice obligations where they conflict. Each one is proven by tests in tests/test_round1_fixes.py unless it says otherwise.

- FIX2-1 A run removes only what it created. A supplied work root must start empty and a run refuses a non empty work root before doing any work, on success and on failure paths alike, so a failed run can never delete a previously kept clone or an unrelated operator file. A work root the run created itself is removed whole, and a pre existing empty work root keeps only what was already inside it, which is nothing the run did not place there.
- FIX2-2 Git mode isolates its seeds from its gates. The scratch clone checkout is hard reset and cleaned between the clean run and every seed, so a gate that writes tracked or untracked files inside the checkout cannot abort the run or poison a later seed. Gates are still expected to be read only judges, and the engine no longer depends on that expectation.
- FIX2-3 The seed pack loader enforces the registry invariants it mirrors. A pack of this format carries exactly twelve entries, every entry field is a non empty piece of text, and ids are unique. A pack that breaks any of those rules is refused.
- FIX2-4 Git mode refusals name the actual problem. A target inside another repository but not at its root is refused as not the root, a repository with no commits is refused as having no commits, and the command line surface prints refusals as one error line with a non zero exit and never as a traceback.
- FIX2-5 The two planting modes judge different material and the contract says so. Git mode judges the committed HEAD of the target because a clone carries only committed state, and copy mode judges the working tree as it stands. An operator with uncommitted edits gets different content scored by the two modes, by construction.

## Slice 3 obligations

Slice 3 changes how widely a seed plants. Earlier slices planted a seed into the first file it applied to and stopped, so a defect class that lived in five files was only ever planted in one of them and the catch table said nothing about the other four. The obligations below state the wider behaviour and amend the earlier planting text where the two conflict.

- G-1 A seed plants into every file where it applies. In both planting modes the seed plants into every non test Python file in the scratch material where its applicability check succeeds, one planting per file at the first matching shape in that file, exactly as a planting inside one file worked before. This obligation amends the planting behaviour behind SLICE-3 and SLICE-4 and the planting step in SLICE2-2, which planted only into the first applicable file, and the amendment is stated here rather than left as a silent conflict between the two texts. Proven by test_plant_seed_covers_every_applicable_file and test_multi_file_fixture_names_every_planted_file.
- G-2 Every result row names every planted file. Each row carries planted_files holding the repo relative paths the seed planted into, in sorted order, and the list is empty when the seed applied nowhere and the row is not applicable. The row keeps planted_file as the first entry of that list, or nothing when the list is empty, so readers of the earlier report shape keep working. The text report keeps the same row and status vocabulary and adds the full planted list under a row whenever a seed planted into more than one file, and the JSON report carries the same list. Proven by test_multi_file_fixture_names_every_planted_file and test_report_lists_every_planted_file_in_text_and_json.
- G-3 Scoring is unchanged under plant everywhere. A gate still judges the fully planted copy or branch as one state, caught when the clean run exits zero and the planted run exits non zero, waved through when both exit zero, gate broken when the clean run fails, exactly as SLICE-5 and SLICE2-3 state. Proven by test_multi_file_fixture_scores_the_fully_planted_state and by the unchanged slice 1 and slice 2 scoring tests.
- G-4 A seed that applies to exactly one file behaves exactly as it did in slice 2. Its planted_files holds that one file, its planted_file equals it, and every verdict on a single file fixture matches the verdict slice 2 produced on the same fixture. Proven by test_single_file_fixture_matches_slice_two_verdicts.
- G-5 In git branch mode the seed commit carries every planted file. The one commit on each throwaway branch holds every file that seed planted, the branch naming from SLICE2-2 is unchanged, and the target git state and files stay byte identical under the work root rules from FIX2-1 and the checkout isolation from FIX2-2. Proven by test_git_mode_branch_commit_carries_every_planted_file and test_git_mode_target_git_state_untouched.
- G-6 The committed examples tell the truth under plant everywhere. The slice 1 example catch table, the two gate example tables, and the seed pack are regenerated through the command line after the planting change, and the README status records any example verdict that changed because of the wider planting and the reason it changed. This obligation amends the claim in SLICE2-5 that copy mode does not change, because copy mode planting is exactly what widened. Proven by test_copy_mode_example_regenerates_byte_identical and test_two_gate_run_scores_each_gate_on_its_own_evidence.

## Round 2 review fixes

The Round 2 red team rejected the slice as first built, because the wider walk reopened a harm Round 1 had closed. A run could write planted content outside the scratch material through a symlink, silently, and three further claims broke on shapes the ordinary fixtures never held. The two axis review added one ordering defect of its own. The obligations below amend the slice 3 obligations and the earlier ones they name where they conflict, and each one is covered by tests in tests/test_round2_fixes.py unless it says otherwise.

Obligation FIX3-1 covers symlink safety. A candidate file that is a symlink is never planted into, and a candidate whose resolution lands outside the scratch root is never planted into, in either mode. A run therefore cannot write through a link to material outside the scratch copies or the scratch clone, and a relative symlink to another file inside the tree is a spelling of that file and never a second planting counted under its own name.

Obligation FIX3-2 covers what counts as a planting. A file counts as planted only when the seed changes its syntax tree. A shape that is already in its planted form, the way a version literal already reading 9.9.9 meets the stale version seed, plants nothing, and when no file changes the seed is not applicable and no branch is made in git mode. The seed commit in git mode therefore always carries changes, and it carries exactly the files the row names.

Obligation FIX3-3 covers test infrastructure. The test file test now also excludes a file named conftest.py, a file named exactly test.py, and any file under a directory named test or testing, beside the shapes it already excluded. A defect can no longer be planted into the harness that runs the gate and scored as a catch against the field.

Obligation FIX3-4 covers unparseable files. A Python file that cannot be parsed is skipped for every seed instead of ending the run, and the report names every such file in an unparseable files list in the JSON report and on a line of its own in the text report when the list is not empty. One stray unparseable file now costs that file its plantings and nothing else. The example JSON reports gain the same list, empty for the demo project, and no verdict in them changes.

Obligation FIX3-5 covers the planted list order. The planted files list is sorted as the rendered repo relative path strings, which is the order G-2 states, and the case where the two orders part, a module file beside a directory that shares its stem, is pinned by a test.

Obligation FIX3-6 covers seed pack field text. Every field of a seed pack entry must hold text with at least one non whitespace character, so a description of spaces alone is refused the way an empty string already was.

## Slice 4 obligations

Slice 4 changes how widely a seed plants inside one file. Slice 3 planted a seed into every file where it applies and stopped at the first matching shape inside each file, so a file where the shape occurs five times received one defect and the gate never faced the other four. The obligations below state the wider behaviour and amend G-1 where the two conflict.

Obligation H-1 covers planting at every matching shape. When a seed plants into a file it plants at every place in that file where its shape matches, not only at the first. This obligation amends G-1 where the two conflict, because G-1 states one planting per file at the first matching shape in that file, and the amendment is stated here rather than left as a silent conflict between the two texts. The change each seed makes at one match is the change it has always made, and only the number of matches planted in one pass changes. A file still counts as planted exactly when the seed changes its syntax tree, as FIX3-2 states, so a file where every occurrence already sits in its planted form plants nothing, while a file where only some occurrences sit in planted form still plants the rest. The planted list still names each planted file once in the order G-2 and FIX3-5 state. Proven by test_three_occurrences_in_one_file_are_all_planted, test_a_partly_planted_file_plants_the_rest, and test_git_mode_branch_commit_carries_the_fully_planted_file.

Obligation H-2 covers where the matching rule lives. Each seed keeps its matching rule and its change in its own apply function in canaryfield/seeds.py, and one call to that function plants at every match in the tree it is given and reports whether it planted anything. plant_seed in canaryfield/engine.py calls the apply function once per file and never repeats a call to reach further matches, so what matches and how it changes is defined in exactly one place for each seed. Proven by test_one_apply_call_plants_every_match.

Obligation H-3 covers the one coherent pass. The matches for one file are collected from the tree as parsed, before any change is made, and each matched node is planted exactly once in that pass. A change made by a planting is never rescanned during the same pass, so a planting cannot create a new match for itself, and a planted shape that would itself match is left exactly as planted and never planted a second time. A matched node that an earlier planting in the same pass removes from the tree is changed in memory and is no longer part of the written file, so the written file shows the outer planting. Proven by test_a_planted_shape_is_not_planted_twice, test_negated_conditions_wrap_exactly_once, test_range_bounds_shift_exactly_once, and test_a_match_inside_a_swallowed_handler_stays_detached.

Obligation H-4 covers the proof that the widening is real. A fixture whose gate exercises only the second occurrence of a shape is waved through when only the first shape is planted and is caught when every shape is planted, and a fixture with three occurrences of one shape in one file shows all three planted in the planted content and is judged on that fully planted file. Proven by test_second_occurrence_only_fixture_flips_with_the_widening and test_three_occurrences_in_one_file_are_all_planted.

Obligation H-5 covers stability everywhere else. A seed that matches at exactly one shape in a file plants exactly as it did in slice 3, the single occurrence fixtures keep their slice 3 verdicts, and the scoring rule from G-3 and the report shape from G-2 do not change. The committed examples regenerate byte identical under the wider planting unless a verdict honestly changes, and any such change is recorded with its reason in the README status in the same change. Proven by test_single_occurrence_fixture_keeps_its_slice_three_verdicts and by the unchanged slice 1, slice 2, and slice 3 tests, the round 1 and round 2 fix tests, and the example regeneration tests.

## Round 3 review fixes

The Round 3 red team found no defect in the widening itself and two defects the wider planting inherited and multiplied, and the standards axis of the two axis review found one disclosed behaviour change carrying no pinning test. The obligations below amend FIX3-1, H-1 and H-2 where they conflict, and each one is covered by tests in tests/test_round3_fixes.py unless it says otherwise.

Obligation FIX4-1 covers symlinks in copy mode. The tree copy preserves symlinks instead of dereferencing them, so a link reaches the planting walk as a link and the guard of FIX3-1 fires in copy mode exactly as it fires in git mode. A relative link to another file inside the tree is therefore never a second planting counted under its own name, and a link pointing at a file outside the target is never planted or judged as field content. Before this fix the copy dereferenced every link, so the guard never saw one in copy mode and an alias was planted and counted under the link name.

Obligation FIX4-2 covers the scope of the wrong variable seed. A return is judged against the parameter list of the function whose own body holds it. The walk that collects a function's returns stops at any nested function or class, and a nested function is judged against its own parameters when the walk of the tree reaches it. Before this fix the walk descended into nested bodies, so a return inside a one parameter nested function was rewritten against the outer function's parameters into a name unbound in its own scope, and the gate catch that followed was a name error rather than the documented defect.

Obligation FIX4-3 covers the swallowed exception seed and two readings of the slice 4 text. A handler already reduced to a bare pass is skipped by that seed and the later handlers in the file are planted, and that behaviour is pinned by a named test rather than resting on disclosure alone. Obligation H-1 is read with the carve out H-3 states, so a match an earlier planting in the same pass removes from the tree is changed in memory and never reaches the written file, and the written file shows the outer planting alone. The every match rule lives in each seed apply function rather than in a repeating loop in plant_seed for the reason H-2 gives and one more, which is that several seeds match their own planting, so a loop that repeated a call until nothing matched would never terminate.

## Slice 5 obligations

Slice 5 grows the seed registry. The twelve seeds of the earlier slices cover many defect families and leave real ones unplanted, and the seed pack format has no room to grow because FIX2-3 pins its single version to exactly twelve entries. The obligations below add four seeds and version the pack so both counts stay pinned, each to its own format. The obligations amend SLICE-1 and SLICE2-7 and FIX2-3 where they conflict, and the amendments are stated here rather than left as silent conflicts between the texts. Two candidate families were set aside while the four were chosen, and the reasons belong in this record. An inverted membership test was set aside because seed-02 already flips in to not in inside its comparison table, so a membership seed would have planted a family the registry already holds. A mutated mutable default argument was set aside because the defect lives in how a body uses a shared default across calls and has no single node shape to collect, so planting it would have meant rewriting function bodies by pattern rather than planting one collected match per occurrence.

Obligation I-1 covers the grown registry. The registry holds sixteen seeds with unique stable ids running in order from seed-00 to seed-15. The original twelve seeds keep their ids and their names and defect classes and descriptions and apply behaviour exactly as the earlier slices left them, and the four new seeds take the next four ids. This obligation amends SLICE-1, which pinned the registry at exactly twelve. Proven by test_registry_has_sixteen_unique_seeds and test_seed_zero_is_the_stale_version_string and test_seed_metadata_is_complete.

Obligation I-2 covers seed-12, swapped operand order. The seed plants at every binary operation whose operator is subtraction or division or floor division or modulo by exchanging the left and right operands. Those operators are not commutative, so the order of the operands decides the result and an exchanged pair computes a different value from the same inputs while the expression still reads as plausible code. The matches are collected from the tree as parsed and each is planted exactly once in one pass, under the discipline of H-2 and H-3, so an operation nested inside another matched operation is planted once at each level and never twice at the same level. Proven by test_seed_twelve_plants_and_is_caught and test_seed_twelve_plants_at_two_occurrences_in_one_file and test_seed_twelve_not_applicable_without_a_noncommutative_operator.

Obligation I-3 covers seed-13, dropped else branch. The seed plants at every if statement that carries a non empty else branch by removing the else branch. The else branch carries the fallback path for the inputs the condition rejects, and removing it makes those inputs fall through to whatever follows the statement, silently taking a path the code never wrote for them. An elif chain lives in the else branch as one nested if, so removing the else branch removes the whole chain, and the seed says so by its shape rather than sparing chains. The matches are collected and planted under the same discipline as I-2. Proven by test_seed_thirteen_plants_and_is_caught and test_seed_thirteen_not_applicable_without_an_else_branch.

Obligation I-4 covers seed-14, swapped boolean operator. The seed plants at every boolean operation by exchanging and for or and or for and. A compound condition with the wrong connective admits and rejects the wrong cases while every comparison inside it stays right, so the defect hides behind correct looking parts. The matches are collected and planted under the same discipline as I-2. Proven by test_seed_fourteen_plants_and_is_caught and test_seed_fourteen_not_applicable_without_a_compound_condition.

Obligation I-5 covers seed-15, dropped await. The seed plants at every await expression by replacing the await with the expression it awaited. Without the await the caller holds a coroutine object instead of the result it waited for, and the awaited work is handed to no scheduler by that expression, so the value is wrong in kind and the work may never run. The matches are collected from the tree as parsed with their parents, and each is planted exactly once, deepest first, so an await nested inside another await is planted at each level without the outer planting stranding the inner one on a detached node. Proven by test_seed_fifteen_plants_and_is_caught and test_seed_fifteen_not_applicable_without_an_await.

Obligation I-6 covers the versioned pack. Writing a seed pack now writes the format canaryfield-seeds/2 carrying sixteen entries, one per seed in the grown registry. The loader accepts both formats and holds each to its own count, refusing a canaryfield-seeds/1 pack that does not carry exactly twelve entries and a canaryfield-seeds/2 pack that does not carry exactly sixteen, and refusing any other format string the way it always has. The field rules of FIX2-3 and FIX3-6 apply to both versions unchanged, so every entry of either version carries an id and a name and a defect class and a description, each a non empty piece of text, and ids are unique within the pack. This obligation amends SLICE2-7 and FIX2-3, which spoke of one format carrying exactly twelve entries. Proven by test_seed_pack_round_trip and test_seed_pack_via_cli and test_version_one_pack_still_loads_the_original_twelve and test_a_pack_whose_count_disagrees_with_its_version_is_refused.

Obligation I-7 covers the committed examples under the grown registry. The slice 1 catch table and the two gate tables and the seed pack are regenerated through the command line after the registry change, and each table now carries sixteen rows and the pack is a version 2 pack. No verdict on the original twelve seeds changes on the demo project, because each seed still plants alone in its own copy or branch and a new seed cannot reach into another seed planting. The README status records what the new seeds honestly score on the demo project. This obligation amends the example stability readings of SLICE2-5 and G-6 and H-5 for this slice the way those obligations amended them before. Proven by test_copy_mode_example_regenerates_byte_identical and test_two_gate_example_shows_an_honest_disagreement and test_two_gate_run_scores_each_gate_on_its_own_evidence.

## Round 4 review fixes

The Round 4 review recorded two Minor findings and one design question for the owner, and the obligations below close them. The red team approved the slice with no Critical and no Major findings.

Obligation FIX5-1 covers the pack loader and the ids it accepts, and it records an owner decision. A pack version is a count and field contract. The loader holds each version to its entry count and applies the field rules of FIX2-3 and FIX3-6 to every entry, and it does not compare the ids a hand written pack carries against the registry for that version, so a version 1 pack carrying ids from the grown registry loads as data, and the round trip tests pin registry equality only for packs this tool writes. The sentence in SLICE2-7 about loading returning the same twelve ids and defect classes describes that round trip over the built in registry rather than a promise about hand written packs, and this obligation records that reading so the two texts cannot be taken to promise more than the loader does. Pinning each version to its id set is recorded as debt for a later round rather than decided here, because refusing hand written packs on id grounds would change what the format accepts beyond what any obligation in this round claims.

The slice 5 preamble now records why two candidate families were set aside, an inverted membership test because seed-02 already flips in to not in, and a mutated mutable default argument because the defect has no single node shape to collect. The README status lines from the slice 2 era are reworded in this pass so the two gate example reads at its current eleven disagreements and the seed pack bullet names both format versions. Seed-14 gains a content level test in tests/test_round4_fixes.py that pins its swapped operators in the rendered tree, bringing it to the same standard as its three sibling seeds.

Amendment note on FIX5-1. Slice 6 supersedes the decision recorded in FIX5-1 on the one point it left open. The loader now pins each version to its id set and to the definition fields of its entries under obligations J-1 and J-2, so the reading recorded there, that a version 1 pack carrying ids from the grown registry loads as data, no longer holds. The rest of FIX5-1 stands, including its reading of the SLICE2-7 sentence as a statement about the round trip this tool writes.

## Slice 6 obligations

Slice 6 pays the debt FIX5-1 recorded. That obligation held a pack version to its entry count and its field rules and expressly left the ids a hand written pack carries unverified against the registry for that version, recording the pinning of each version to its id set as debt for a later round. This round pays it, and slice 6 also settles how far the verification reaches into the other entry fields. The obligations below amend FIX5-1 and I-6 where they conflict, and the amendments are stated here rather than left as silent conflicts between the texts.

Obligation J-1 covers the id set of a pack. The loader refuses a pack whose ids are not exactly the id set of its declared format version, the original twelve ids seed-00 to seed-11 for canaryfield-seeds/1 and the sixteen ids seed-00 to seed-15 for canaryfield-seeds/2. The order of the entries in the file does not matter for acceptance, because the comparison is a set comparison. A missing id, an invented id, and a grown registry id carried inside a version 1 pack each refuse the pack. The set rule composes with the rules that already stand rather than replacing any of them, so the format check and the count check of I-6 run first, the field rules of FIX2-3 and FIX3-6 and the duplicate id refusal run next over every entry, and the set comparison runs last of those over a pack that has passed all of them, with the definition comparison of J-2 after it, and no refusal path an earlier obligation promised is lost or reworded. The refusal is a named error in the style of the count refusal and says the pack ids do not match its format. Proven by test_a_version_one_pack_carrying_a_grown_registry_id_is_refused and test_a_version_one_pack_with_an_invented_id_is_refused and test_a_version_two_pack_with_an_invented_id_is_refused and test_pack_entry_order_does_not_matter_for_acceptance.

Obligation J-2 covers the definition fields of an entry. For every entry the loader also compares the name and the defect class against the registry seed that carries the same id within the pack version, and refuses the pack when either one disagrees, naming the entry and the field in the error. Those two fields are the definition a consumer reads, because the pack exists so other tools in the line can consume the same seed definitions, and a pack whose seed-03 carries a different defect class than the registry seed-03 is a different registry wearing the right ids, scored under labels its seeds never had. The description is not compared, because it is prose written for a human reader and two wordings of one description do not make two registries, and pinning prose would refuse packs over wording edits that change no definition. The unverified description is a stated limit of the format and is pinned as one, so the limit cannot tighten silently in a later round. Proven by test_a_pack_entry_whose_defect_class_disagrees_with_the_registry_is_refused and test_a_pack_entry_whose_name_disagrees_with_the_registry_is_refused and test_a_pack_entry_description_is_prose_and_is_not_verified.

Obligation J-3 covers what does not change. Writing a pack still writes the current format from the built in registry, and a pack this tool writes loads exactly as it did, and a hand built version 1 pack carrying the original twelve registry entries still loads. The committed examples do not move, because this slice changes only what the loader accepts and the pack this tool writes is registry data, so every committed example regenerates byte identical through the command line. Proven by test_seed_pack_round_trip and test_seed_pack_via_cli and test_version_one_pack_still_loads_the_original_twelve and test_copy_mode_example_regenerates_byte_identical.


## Round 5 review fixes

The Round 5 red team approved the slice and the two axis review recorded two Minor wording and pinning points, and this section closes them. No behaviour changes in this pass.

The two refusal tests under J-2 now match the full refusal text, naming the entry and the field, where they previously matched only the shared middle of the message, so a later change that dropped the entry id or the field name from that refusal would fail the tests the obligation names.
